    -> code that reads weapon state at death must also sync it periodically.

  doors model only Lock/Unlock/Open/Close/Toggle inputs + m_bLocked/m_eDoorState.

PITFALLS (code)
  module tables: methods and fields share one namespace (M:Container(id) overwrote M.Container = class).
  modes: never name a round handler M:Start/M:Stop/M:Init (module lifecycle) -> Begin; round:Every needs an id
    string first; round.mode is the mode id (string), not a table.
  ctx:Require(id) errors for ids not in requires/optional: a package using weapons:Register must list 'weapons'.
  command names are global: a second ctx.commands:Add of a name owned by another module fails the module Start
    (nc_give is weapons'; economy uses nc_givemoney). Re-adding an own name replaces the command (and its
    privilege). Handlers get nil for the server console (the engine's NULL is converted).
  permissions: never check IsSuperAdmin/IsAdmin in modules: declare a privilege and ask ctx.permissions:Can (the
    fallback ranks live in the service); a client Can is for the UI only; Refresh(ply) after changing a group.
  component fields cannot be optional: use uint 0 for 'none' (e.g. a player entity index); the Lua keyword
    'until' cannot be a field accessed as data.until -> time fields are named 'ends'.
  movement.speed factors: modules that change theirs must call movement:Refresh(ply) (speeds are set, not polled).
  inventory: Give(player) reasons come from _Store (size/weight beat "full"); pockets take size 1 only (kits in
    boots without equipment drop sacks/rifles -> missed); Move into a place needs inventory:Open(ply, place)
    first (CanReach: watching set + InReach of the eyes), else 'reach' before any canMove question;
    SpawnPlace returns ent, container - PlaceOf takes the entity.
  names: player-facing names go through players:Name(ply) (Reduce players.name); admin/console output uses Nick.
  bridge: gm.PlayerDeathNotice false skips base PlayerDeath (no kill feed); the bridge still sets
    NextSpawnTime/DeathTime.
  rounds call game.CleanUpMap at round start: map entities (doors) are NEW objects -> look them up again by
    MapCreationID (the emulator keeps MapCreationID across cleanup); mode Cleanup runs only when the next round
    starts (after endTime 8 s), not at round:End; loot rule spawns one tick after Setup (round:After(0)).
  questions: two modules answering doors.canRam -> Query takes the first non-nil; answer nil to allow and false
    to deny, then the order does not matter.
  law Jail inside a restraints.tied handler is safe: restraints:Tie emits after its state is set.
  rounds start preparing as soon as minPlayers are ready (same tick): with minPlayers 2 only the first two ready
    are Participants, the rest are late joiners of preparing (Deal tests: call M:Deal on a fake round).
