# Модуль `storage` — постоянные данные

Данные модулей, которые переживают смену карты и перезапуск сервера: банковские счета, владельцы дверей, точки лута, профили игроков. Два вида хранилищ за одним API и два бэкенда на выбор в настройках.

| | |
|---|---|
| Интерфейс | `storage` (только сервер) |
| Зависимости | — |
| Слушает | `gm.ShutDown` |
| Испускает | `storage.flushed (ns)` |
| Команды | `nc_storage [flush \| <пространство> [ключ]]` (админ) |
| Настройки | `folder` = `"nextcity"`, `flushDelay` = 2 с, `pretty` = `false`, `backend` = `"json"` |

## Виды хранилищ

| | Пространство (`Open`) | Коллекция (`Collection`) |
|---|---|---|
| Для чего | небольшие общие данные: счета, двери, точки | записи по ключу: профили тысяч игроков |
| Чтение | все ключи сразу при открытии | запись читается при первом `Get` и держится до `Release` |
| Значения | всё, что сохраняет JSON | таблицы (запись), ключ — до 80 байт |
| JSON | `data/nextcity/<ns>.json` | папка `data/nextcity/<ns>/`, файл на запись `<ключ>.json` |
| SQLite | таблица `nextcity_<ns>`, пишутся только изменённые ключи | таблица `nextcity_<ns>`, строка на запись |

## API

```lua
local storage = ctx:Require("storage")
local key = storage:PlayerKey(ply)                -- SteamID64, для ботов "bot_<имя>"

-- Пространство: всё в памяти.
local bank = storage:Open("bank")
bank:Set(key, { cash = 500 })
local account = bank:Get(key)
account.cash = account.cash + 100
bank:Touch(key)                                   -- таблица изменена на месте (Touch() — что угодно)
bank:Delete(key); bank:Keys(); bank:Count(); bank:Each(); bank:Flush()

-- Коллекция: запись на ключ, загрузка по требованию.
local profiles = storage:Collection("profiles")
local record = profiles:Get(key)                  -- таблица или nil; читается один раз
profiles:Set(key, { kills = 0 })                  -- nil удаляет
record.kills = record.kills + 1
profiles:Touch(key)
profiles:Release(key)                             -- записать, если менялась, и выгрузить (игрок ушёл)
profiles:Has(key); profiles:Delete(key); profiles:Flush([key])
profiles:Keys(); profiles:Count()                 -- читают папку или таблицу: для команд, не для горячих путей
profiles:LoadedKeys()                             -- ключи записей в памяти

storage:Backend()                                 -- "json" или "sqlite"
```

## Бэкенды

- `json` (по умолчанию) — файлы в `garrysmod/data/<folder>/`. Имя файла записи — ключ, где всё, кроме `a-z` и `0-9`, записано как `_xx` (байт в hex): `bot_Kevin` → `bot_5f_4bevin.json`.
- `sqlite` — библиотека `sql` движка (файл `garrysmod/sv.db`): таблица `<folder>_<ns>` со столбцами `key TEXT PRIMARY KEY` и `value TEXT` (JSON; у пространств значение обёрнуто в массив `[value]`). Запись — одной транзакцией. Новая таблица один раз забирает JSON-данные того же имени, поэтому смена бэкенда сохраняет данные (JSON-файлы остаются на месте). Без библиотеки `sql` — предупреждение и `json`.

Выбор бэкенда — `lua/nextcity/config/server.lua`:

```lua
return { modules = { settings = { storage = { backend = "sqlite" } } } }
```

## Правила

- Имя пространства или коллекции — строчные буквы, цифры и `_`; одно имя не может быть и пространством, и коллекцией.
- Ключи — непустые строки. Строковые ключи вида `"12"` внутри значений остаются строками.
- Изменения копятся: запись через `flushDelay` секунд после первого изменения (одной записью), при выключении сервера, при остановке модуля и по `nc_storage flush`.
- Повреждённый JSON-файл переносится в `<имя>_corrupt.txt`, данные начинаются пустыми, в лог — предупреждение.
- Ошибка SQL пишется в лог (`sql: ...`), изменённые ключи остаются отмеченными и пишутся при следующей записи.

## Проверить в реальном GMod

- Время записи больших пространств (тысячи ключей) и отсутствие подвисаний тика; то же для коллекции с тысячами файлов (`Keys` на `file.Find`).
- Бэкенд `sqlite`: создание таблиц в `sv.db`, перенос JSON-данных при первом запуске, `nc_storage` после перезапуска.
- Имена файлов записей с `_xx` в папке `data` на Windows и Linux.
