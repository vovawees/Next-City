# Как участвовать

Перед работой прочитайте [архитектуру](docs/ARCHITECTURE.md) и [стиль кода](docs/CODESTYLE.md): слои, контракты модулей и правила производительности обязательны для любого вклада.

## Локальная проверка

Нужны [LuaJIT 2.1](https://luajit.org/) и [glualint](https://github.com/FPtje/GLuaFixer/releases); игра для тестов не нужна — модули проверяются в эмуляции GMod (`tests/gmod/env.lua`).

```sh
luajit tests/run.lua               # все спеки: юнит-тесты ядра и модули в эмуляции GMod
luajit tests/run.lua doors         # только спеки, в пути которых есть "doors"
luajit tests/bench.lua [nojit]     # бенчмарки горячих путей — сравнить до и после
glualint lint gamemodes tests lua  # линтер (настройки в .glualint.json)
```

Тесты должны пройти без единого `failed`, линтер — ничего не вывести. Проверки запускаются локально перед каждым коммитом; CI в проекте не используется.

## Правила

- `main` всегда рабочий. Новая работа — в ветке `feat/<name>` или `fix/<name>`, слияние через PR после зелёных тестов и чистого линтера.
- Один логический шаг — один коммит, сообщения по [Conventional Commits](https://www.conventionalcommits.org/): `feat(doors): …`, `fix(rounds): …`, `docs: …`, `test: …`; ссылка на задачу — `Refs #N`, закрывающий коммит — `Closes #N`.
- Не копируйте код из Z-City, Homigrad и других проектов с несовместимой лицензией — только собственные реализации.
- Новое архитектурное решение — строка в таблице «Ключевые решения» в `docs/ARCHITECTURE.md`.
- Контент (оружие, патроны, предметы, режимы) не добавляется в ядро — только в пакеты поверх него ([D15](docs/ARCHITECTURE.md#4-модули)).
- Строки интерфейса — только ключи переводов ([D13](docs/ARCHITECTURE.md#12-локализация)), сразу в `lang/en/` и `lang/ru/`.
- В репозитории и файлах настроек нет паролей и ключей: настройки уходят клиентам вместе с кодом.
- Отправляя вклад, вы соглашаетесь с разделом 7 [лицензии](LICENSE): автор получает право использовать и перелицензировать ваш вклад.

## Новый модуль

1. Скопируйте [`modules/example`](gamemodes/nextcity/gamemode/modules/example/README.md): в ядро — систему, в пакет (`lua/nextcity/modules/<id>/` своего аддона) — контент и режимы.
2. Опишите манифест `module.lua`: `requires` и `optional`, файлы по realm (`sh`, `sv`, `cl`), `config`, сетевые сообщения (`net`) и компоненты по схемам.
3. Другие модули — только через их API, события и вопросы шины, без чужих внутренних полей; хуки движка — события моста `gm.*`.
4. README модуля: что делает, настройки, API, команды и раздел «Проверить в реальном GMod».
5. Спек в `tests/gmod/<id>_spec.lua` (путь — в списке `SPECS` в `tests/run.lua`).

## Документы вместе с кодом

Изменение поведения обновляет README модуля, а при необходимости — [архитектуру](docs/ARCHITECTURE.md), [роадмап](docs/ROADMAP.md) и [README](README.md) (таблицы модулей, режимов, команд). Технические заметки для следующих сессий разработки — в `.ai/` (плотный текст на английском, начинать с `.ai/README.txt`); карту модулей для них печатает `luajit tools/modmap.lua`, карту API — `luajit tools/apimap.lua > .ai/api.txt`.
