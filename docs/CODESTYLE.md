# Стиль кода и правила

## Язык и синтаксис

- Lua 5.1 / LuaJIT 2.1, **только стандартный синтаксис**: `~=`, `and`, `or`, `not`, комментарии `--`. Без `!=`, `&&`, `||`, `//`, `continue`.
- Отступы — табы, длина строки — до 120 символов, строки в двойных кавычках.
- Файл модуля начинается с `local M = NC.Module("<id>")`; всё остальное в файле — `local`.

## Именование

| Что | Стиль | Пример |
|---|---|---|
| локальные переменные, параметры, поля данных | camelCase | `local bloodLoss`, `state.heartRate` |
| константы | UPPER_SNAKE | `local MAX_BLOOD = 5000` |
| библиотеки и «классы» | PascalCase | `Events`, `FSM` |
| функции API и методы | PascalCase | `bus:Emit()`, `M:ApplyTreatment()` |
| id модулей и интерфейсов | snake_case | `organism_realistic` |
| события | `модуль.событие` | `organism.unconscious` |
| конвары и команды | `nc_` + snake_case | `nc_perf` |
| файлы | префикс realm | `sh_defs.lua`, `sv_sim.lua`, `cl_hud.lua` |

## Глобалы и состояние

- Единственный глобал проекта — `NC`.
- Состояние не хранится полями на сущностях (`ply.foo = ...`): медленный доступ через метатаблицу, утечки и неявная связность. Используем хранилище компонентов (этап M1).

## Модули

- Манифест `module.lua` с явным списком файлов по realm.
- Публичный API — методы `M`; приватное — `local function`.
- Подписки и задачи — только через `ctx:On` и `ctx:Every`: они автоматически снимаются при остановке модуля.
- Другие модули — только через `ctx:Require("<interface>")` и только объявленные в манифесте.
- События, которые модуль испускает, и его конфиг документируются в шапке файла или в `README.md` модуля.
- Строки интерфейса — только ключи переводов (`ctx.i18n:T("module.key", params)`); новые ключи добавляются в `lang/en/` и `lang/ru/`. Логи и dev-команды — на английском.
- Сетевые сообщения — только в секции `net` манифеста и через `ctx.net`; модули не вызывают `util.AddNetworkString` и `net.Receive` сами. Полное состояние игроку отправляется по `net.ready`.
- Данные сущностей — компоненты в секции `components` манифеста и через `ctx.components`, а не поля в таблице сущности и не `SetNW*`. Полное состояние компонентов и их изменения платформа отправляет сама; прямую запись в таблицу данных отмечать `Touch`.

## Ошибки и безопасность

- Ошибки не глушим молча: `ctx.log:Error(...)`.
- Клиенту не доверяем: всё входящее проверяется на сервере (права, дистанция, диапазоны, частота).
- `assert` — для программных ошибок при загрузке и инициализации, не в горячих путях.

## Производительность

1. Не аллоцировать в горячих путях (тик, кадр, рендер, урон): переиспользовать таблицы, не создавать замыкания и `{ ... }` в цикле.
2. Кэшировать глобалы и функции движка в `local` в начале файла: `local CurTime = CurTime`.
3. Игроки и сущности — `player.Iterator()` / `ents.Iterator()`, не `player.GetAll()` в горячем пути.
4. В горячих циклах — массивы и числовой `for`, не `pairs`.
5. Много полей сущности — один раз `local tbl = ent:GetTable()`.
6. Дистанции — `DistToSqr` против квадрата порога.
7. Никаких `timer.Create` на каждую сущность — задачи планировщика (`ctx:Every`).
8. Модули не вешают свои `hook.Add("Think" / "Tick" / "HUDPaint" …)` — только планировщик и конвейеры bridge.
9. Сеть: без `net.WriteTable` и без `SetNW*` для часто меняющихся значений — только схемы и дельты (компоненты).
10. `Material()`, `surface.CreateFont`, `Color()` — при загрузке, не в кадре.
11. Не собирать строки в кадре (`..`, `string.format`) — кэшировать тексты HUD до изменения значения.
12. Оптимизация без замера не принимается: `nc_perf` до и после.

## Коммиты

[Conventional Commits](https://www.conventionalcommits.org/): `feat(organism): ...`, `fix(net): ...`, `perf(scheduler): ...`, `refactor`, `docs`, `test`, `ci`, `chore`. Один логический шаг — один коммит.

- [ ] Модуль использует только объявленные интерфейсы
- [ ] Нет новых глобалов и полей на сущностях
- [ ] В горячем пути нет лишних аллокаций и вызовов C-API
- [ ] Входящие данные клиента проверены; у клиентских сообщений заданы `rate` и `burst`

- [ ] Строки интерфейса — ключи переводов, есть в `lang/en` и `lang/ru`
